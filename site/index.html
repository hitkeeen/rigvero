Prepare your avatar. Keep control.

A planned Blender add-on for preparing VRChat avatars. Instead of one blind fix button, it is designed around a calmer path: inspect the model, review a plan of changes, apply them to a copy — and read a before/after report before anything leaves Blender. Why it exists

Preparation shouldn’t feel like gambling

These are documented user cases from the public CATS issue trackers; the product idea is our response to them, not a survey of all users.

One click, unknown consequences

In CATS issue #236, the automated fix “also removes the neck bone if it works.” When a single button decides what counts as “useless”, you learn it from the result.

Errors instead of answers

Documented cases: #645 — “Fix model turns it white” (author links it to Combine Materials); #357 — a VRoid preparation broken by Fix Model; #665 — translating blend shapes broke the animations that used them, with a request for a rename export.

Mobile visibility is guesswork

CATS issue #691: missing textures and atlas/Material Combiner problems stalled a Quest preparation. How strict the limits are is documented by VRChat itself: texture memory, material slots and physics all count — and the final rank is verified in Unity.

Workflow

Inspect → Prepare → Optimize → Export

Four planned stages instead of one leap of faith. The source model will stay untouched.

01

Inspect

Planned: scan the imported model — rig type, bones, shape keys, materials, texture paths and dependencies. Nothing will be changed at this stage.

02

Prepare

Planned: build an explicit plan — renames from the offline dictionary, merges, removals. Risky steps will wait for your explicit confirmation.

03

Optimize

Planned: apply the plan to a copy within target budgets — merge weights, optimize textures, clean the rig. The original file will never be touched.

04

Export

Planned: a before/after report, a rename ledger (CSV) and a Unity-ready FBX. PC and Mobile variants will be checked separately.

What’s planned

Six ideas, stated honestly

Everything below is planned work, not shipped features. Core first, roadmap after.

Inspect · Plan · Apply

Planned core

No blind fixes. Rigvero will show what it found, propose a plan, apply it to a copy with per-step confirmation, and report what changed — before and after.

Platform Budget Validator

Planned core

Profiles for PC Good, Mobile Good and Mobile Medium with versioned rules. Errors, hiding risks and recommendations will stay separated, and Unity-only checks will be flagged instead of faked.

Offline Rename Ledger

Planned core

A bundled offline dictionary for common and MMD names, collision detection, and a stable original → new map with CSV export — so references can be repaired later.

Atlas & Face Preservation

Roadmap

Planned: preview materials and UVs before optimizing, compare the result with the original, and protect visemes, eyelids and key face areas during atlas work.

Dependency Diagnostics

Roadmap

Planned: importers, texture paths and helper backends will be checked before work starts. Errors will say what happened, what stayed untouched and what to try next — with a copyable, anonymized report.

Reproducible PC/Mobile Variants

Roadmap

One source, two saved recipes: separate output collections and reports with consistent naming, so updating an avatar won’t mean repeating every manual step.

FAQ

Questions

Is Rigvero available for download?

Not yet. The project is at the idea / design stage: no code, no working features, no release — everything described is planned. A repository link will appear with the first release.

Is this a CATS replacement?

Rigvero is inspired by the CATS Blender Plugin and its community, and rethinks the workflow around Inspect → Plan → Apply. It is an independent project with no CATS or NeoNeko code inside. Until Rigvero has a tested release, CATS and its forks remain the practical choice.

Will it guarantee a Good rank or a successful upload?

No. Budget checks in Blender are preflight estimates; the final rank depends on Unity import settings, SDK3 components and bundle size, and is verified in Unity. Any tool promising a guaranteed upload from a .blend file is promising too much.

What about names, MMD models and animations?

The plan: an offline dictionary (no external translator required), author names kept as-is, a stable original → new rename map with CSV export, and warnings about external animation bindings. Rigvero won’t promise to fix unknown Unity animations from inside Blender.
